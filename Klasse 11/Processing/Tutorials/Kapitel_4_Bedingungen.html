4.1

Einfache Bedingungen mit if und else

4.1.1 Kontrollfluss: Nicht immer läuft alles gleich ab

Normalerweise arbeitet Processing den Code von oben nach unten ab. Eine Bedingung kann diesen Kontrollfluss verändern: Ein Code-Block wird nur dann ausgeführt, wenn die geprüfte Aussage wahr ist.

Bedingung prüfenIst die Aussage wahr?
→
trueCode-Block ausführen
→
danachnormal weiterarbeiten

Ist die Bedingung false, überspringt Processing den zugehörigen Block. Anschließend läuft das Programm unterhalb der Bedingung normal weiter.

4.1.2 Aufbau einer if-Anweisung

Schlüsselwortif
Prüfung(Bedingung)
Aktion{ Code-Block }
Grundform einer if-Anweisung
if (Bedingung) {
  // Wird nur bei true ausgeführt
  Anweisung;
}

Im nächsten Beispiel wird der Kreis rechts von der Fenstermitte orange. Links bleibt er blau.

Beispiel: Farbe abhängig von mouseX
void setup() {
  size(600, 400);
  noStroke();
}

void draw() {
  background(235);
  fill(40, 150, 220); // zunächst blau

  if (mouseX > width / 2) {
    fill(255, 140, 40); // rechts: orange
  }

  ellipse(mouseX, mouseY, 70, 70);
}
Vor der Bedingung: Die Füllfarbe wird in jedem Durchlauf auf Blau gesetzt.
Bei true: Die orange Farbe ersetzt Blau, bevor der Kreis gezeichnet wird.

4.1.3 Vergleichsoperatoren

Eine Bedingung ist ein boolescher Ausdruck. Das bedeutet: Das Ergebnis ist immer entweder true oder false.

OperatorBedeutungBeispiel
>größer alsx > 100
<kleiner alsx < 100
>=größer oder gleichpunkte >= 50
<=kleiner oder gleichalter <= 18
==gleichx == 100
!=ungleichx != 100
Wichtig für Processing: Tippe die Operatoren immer mit den einzelnen Tastaturzeichen: >=, <= und !=. Die mathematischen Einzelzeichen ≥, ≤ und ≠ gehören nicht in den Quellcode.
Zuweisung oder Vergleich? x = 100; speichert einen Wert. x == 100 prüft dagegen, ob der aktuelle Wert 100 ist. Für den Gleichheitsvergleich brauchst du zwei Gleichheitszeichen.

4.1.4 Code-Blöcke und Einrückung

Die geschweiften Klammern fassen mehrere Anweisungen zu einem Code-Block zusammen. Alle Anweisungen im Block gehören zur Bedingung.

Mehrere Anweisungen im if-Block
if (mousePressed) {
  fill(255, 80, 80);
  strokeWeight(5);
  ellipse(mouseX, mouseY, 100, 100);
}

Rücke die Zeilen im Block ein. Die Einrückung ändert zwar nicht die Bedeutung des Programms, macht aber sofort sichtbar, welche Zeilen zusammengehören. Processing kann den Code über Bearbeiten → Autoformatierung oder mit Strg+T automatisch einrücken.

Verschachtelte Bedingungen: Ein Code-Block darf eine weitere if-Anweisung enthalten. Die zweite Bedingung wird dann nur geprüft, wenn Processing den äußeren Block ausführt.

4.1.5 if–else: Zwei mögliche Wege

Mit else legst du fest, was geschehen soll, wenn die Bedingung falsch ist. Bei einer if–else-Anweisung wird immer genau einer der beiden Blöcke ausgeführt.

Links blau, rechts orange
void draw() {
  background(235);

  if (mouseX > width / 2) {
    fill(255, 140, 40); // Bedingung ist wahr
  } else {
    fill(40, 150, 220); // Bedingung ist falsch
  }

  ellipse(mouseX, mouseY, 70, 70);
}
Zusammengehörig: Zwischen dem schließenden } des if-Blocks und else darf keine weitere Anweisung stehen.

4.1.6 Beispiel: Ein Ball erscheint wieder links

Der Ball bewegt sich nach rechts. Sobald seine Position größer als die Fensterbreite ist, wird ballX wieder auf 0 gesetzt.

Bewegung mit Rücksprung
int ballX = 0;
int geschwindigkeit = 4;

void setup() {
  size(600, 300);
}

void draw() {
  background(235);
  ellipse(ballX, height / 2, 40, 40);

  ballX = ballX + geschwindigkeit;

  if (ballX > width) {
    ballX = 0; // links neu beginnen
  }
}
Warum nicht ballX == width? Bei einer Geschwindigkeit von 4 kann der Wert über die exakte Fensterbreite springen. > oder >= funktioniert deshalb zuverlässiger.
4.2

Mehrere Fälle mit else if

4.2.1 Mehr als zwei Möglichkeiten

Mit else if kannst du weitere Bedingungen ergänzen. Processing prüft sie von oben nach unten. Sobald eine Bedingung wahr ist, wird ihr Block ausgeführt und die restliche Kette übersprungen.

Allgemeiner Aufbau
if (Bedingung1) {
  // erster Fall
} else if (Bedingung2) {
  // zweiter Fall
} else {
  // alle übrigen Fälle
}
Genau ein Weg: In einer zusammenhängenden if–else if–else-Kette wird höchstens ein Code-Block ausgeführt.

4.2.2 Die Reihenfolge der Bedingungen ist wichtig

Beginne bei gestaffelten Grenzwerten mit dem strengsten beziehungsweise größten Wert. Sonst kann ein allgemeiner Fall einen genaueren Fall abfangen.

Bewertung nach Punktzahl
int punkte = 84;

if (punkte >= 90) {
  println("sehr gut");
} else if (punkte >= 75) {
  println("gut");
} else if (punkte >= 50) {
  println("bestanden");
} else {
  println("nicht bestanden");
}

Bei 84 Punkten ist die erste Bedingung falsch, die zweite aber wahr. Deshalb wird "gut" ausgegeben; die weiteren Bedingungen werden nicht mehr geprüft.

4.2.3 Beispiel: Drei Bildschirmbereiche

Die Mausposition entscheidet, welche Hintergrundfarbe angezeigt wird.

Linkes, mittleres und rechtes Drittel
void setup() {
  size(600, 300);
}

void draw() {
  if (mouseX < width / 3) {
    background(120, 190, 240); // links
  } else if (mouseX < 2 * width / 3) {
    background(120, 210, 160); // Mitte
  } else {
    background(255, 180, 90); // rechts
  }
}
Warum genügt im zweiten Fall mouseX < 2 * width / 3? Dieser Fall wird nur geprüft, wenn das linke Drittel bereits ausgeschlossen wurde.
4.3

Boolesche Ausdrücke verknüpfen

4.3.1 Logisches UND: &&

Ein logisches UND ist nur dann wahr, wenn beide Teilaussagen wahr sind. In Processing schreibst du dafür &&.

ABA && B
truetruetrue
truefalsefalse
falsetruefalse
falsefalsefalse
Ein Wert liegt zwischen zwei Grenzen
int x = 150;

if (x > 100 && x < 300) {
  println("x liegt im Bereich");
}
Nicht wie in Mathematik schreiben: 100 < x < 300 ist in Processing keine geeignete Bereichsprüfung. Formuliere zwei Vergleiche und verbinde sie mit &&.

4.3.2 Logisches ODER: ||

Ein logisches ODER ist wahr, sobald mindestens eine Teilaussage wahr ist. Das Zeichen | erreichst du unter Windows meist mit Alt Gr + <.

ABA || B
truetruetrue
truefalsetrue
falsetruetrue
falsefalsefalse
Außerhalb des Fensters
if (ballX < 0 || ballX > width) {
  println("Der Ball ist außerhalb.");
}

4.3.3 Logisches NICHT: !

Das Ausrufezeichen kehrt einen Wahrheitswert um: Aus true wird false und aus false wird true.

A!A
truefalse
falsetrue
Beispiel: nicht pausiert
boolean pausiert = false;

if (!pausiert) {
  println("Die Animation läuft.");
}

4.3.4 Klammern und Priorität

Processing wertet zuerst !, dann && und zuletzt || aus. Setze bei gemischten Ausdrücken trotzdem Klammern. Dadurch wird deine Absicht deutlich und Fehler lassen sich leichter vermeiden.

Lesbar geklammerte Bedingung
if ((punkte >= 50 && anwesend) || sonderregel) {
  println("Bedingung erfüllt");
}
Normalfall: Mindestens 50 Punkte und Anwesenheit sind erforderlich.
Alternative: Eine aktive Sonderregel reicht ebenfalls aus.

4.3.5 Beispiel: Ein Ball prallt an beiden Rändern ab

Am linken oder rechten Rand soll die Bewegungsrichtung wechseln. Beide Fälle führen dieselbe Anweisung aus und können deshalb mit ODER verbunden werden.

Richtungswechsel am Fensterrand
int ballX = 100;
int geschwindigkeit = 4;

void setup() {
  size(600, 300);
}

void draw() {
  background(235);
  ellipse(ballX, height / 2, 40, 40);

  ballX = ballX + geschwindigkeit;

  if (ballX < 0 || ballX > width) {
    geschwindigkeit = -geschwindigkeit; // Richtung umkehren
  }
}
Vorzeichen umkehren: Aus 4 wird −4, beim nächsten Randkontakt wieder 4. Dadurch bewegt sich der Ball abwechselnd nach rechts und links.
4.4

Boolesche Variablen

4.4.1 true und false speichern

Eine Variable vom Datentyp boolean kann genau zwei Werte speichern: true oder false. Sie eignet sich besonders für Zustände mit zwei Möglichkeiten.

ZustandMögliche Variable
Animation läuft oder pausiertboolean laeuft = true;
Objekt sichtbar oder unsichtbarboolean sichtbar = true;
Licht an oder ausboolean lichtAn = false;

4.4.2 Eine boolesche Variable direkt als Bedingung

Eine boolesche Variable ist bereits eine vollständige Bedingung. Du musst sie nicht noch mit true vergleichen.

Play und Pause
int ballX = 0;
boolean laeuft = true;

void draw() {
  background(235);
  ellipse(ballX, 100, 40, 40);

  if (laeuft) {
    ballX = ballX + 3;
  }
}
Kürzer und klarer: Schreibe if (laeuft) statt if (laeuft == true).

4.4.3 Einen Zustand umschalten

Mit dem NICHT-Operator kannst du einen Zustand bei jedem Tastendruck umkehren. Diese Technik nennt man auch Toggle.

Zwischen Play und Pause wechseln
void keyPressed() {
  laeuft = !laeuft; // true wird false und umgekehrt
}
laeuft enthält zunächst beispielsweise true.
!laeuft ergibt dann false.
Das Ergebnis wird wieder in laeuft gespeichert.

4.4.4 Das Ergebnis eines Ausdrucks speichern

Auch das Ergebnis eines Vergleichs oder einer Verknüpfung kann in einer booleschen Variablen gespeichert werden.

Bereichsergebnis merken
int ballX = 180;
boolean imBereich = false;

imBereich = ballX > 100 && ballX < 300;

if (imBereich) {
  println("Der Ball liegt im markierten Bereich.");
}

Die Variable macht eine längere Bedingung lesbarer und erlaubt es, das Ergebnis später an einer anderen Stelle erneut zu verwenden.

4.5

Tastatur- und Maustasten unterscheiden

4.5.1 Einmalige oder kontinuierliche Reaktion

Für Tastatur und Maus gibt es jeweils zwei unterschiedliche Möglichkeiten. Entscheidend ist, ob eine Aktion einmal beim Drücken oder dauerhaft während des Gedrückthaltens stattfinden soll.

Gewünschte ReaktionTastaturMaus
einmal beim DrückenkeyPressed()mousePressed()
solange gedrücktkeyPressed in draw()mousePressed in draw()
Klammern beachten: keyPressed() ist eine Ereignisfunktion. keyPressed ohne Klammern ist eine boolesche Systemvariable. Dasselbe gilt für mousePressed() und mousePressed.

4.5.2 Buchstaben und andere Zeichen mit key

Die Systemvariable key enthält die zuletzt gedrückte Zeichentaste. Ein einzelnes Zeichen hat den Datentyp char und steht in einfachen Anführungszeichen.

Auf a und d reagieren
int x = 300;

void draw() {
  background(235);
  ellipse(x, 150, 40, 40);

  if (keyPressed) {
    if (key == 'a') {
      x = x - 3; // nach links
    }
    if (key == 'd') {
      x = x + 3; // nach rechts
    }
  }
}
Groß- und Kleinschreibung: 'a' und 'A' sind zwei verschiedene Zeichen.

4.5.3 Pfeiltasten mit keyCode

Pfeiltasten erzeugen kein normales Schriftzeichen. Deshalb vergleichst du die Systemvariable keyCode mit Konstanten wie LEFT, RIGHT, UP oder DOWN.

Flüssige Steuerung mit Pfeiltasten
int x = 300;

void setup() {
  size(600, 300);
}

void draw() {
  background(235);
  ellipse(x, 150, 40, 40);

  if (keyPressed && key == CODED) {
    if (keyCode == LEFT) {
      x = x - 3;
    } else if (keyCode == RIGHT) {
      x = x + 3;
    }
  }
}

Weil die Abfrage in draw() steht, bewegt sich der Kreis flüssig, solange eine Pfeiltaste gehalten wird.

4.5.4 Maustasten mit mouseButton

Innerhalb von mousePressed() kannst du mit mouseButton zwischen linker, rechter und mittlerer Maustaste unterscheiden.

Farbe mit Maustasten wählen
int rot = 40;
int gruen = 150;
int blau = 220;

void draw() {
  background(235);
  fill(rot, gruen, blau);
  ellipse(width / 2, height / 2, 100, 100);
}

void mousePressed() {
  if (mouseButton == LEFT) {
    rot = 40; gruen = 150; blau = 220;
  } else if (mouseButton == RIGHT) {
    rot = 255; gruen = 140; blau = 40;
  }
}
Mögliche Werte: Für mouseButton stehen die Konstanten LEFT, RIGHT und CENTER zur Verfügung.
Hinweis: Auf einem Touchpad oder Tablet steht nicht immer eine rechte oder mittlere Maustaste zur Verfügung. Die linke Maustaste beziehungsweise ein normaler Klick funktioniert am zuverlässigsten.
4.6

Typische Fehler

Ein Gleichheitszeichen statt zwei

x = 100 ist eine Zuweisung. Eine Gleichheitsprüfung wird mit x == 100 geschrieben.

Semikolon direkt hinter der Bedingung

Schreibe nicht if (x > 100);. Das Semikolon beendet die Anweisung zu früh; der folgende Block gehört dann nicht wie beabsichtigt zum if.

Geschweifte Klammern fehlen oder stehen falsch

Markiere jeden Code-Block mit { und } und lasse den Code automatisch formatieren. So werden falsche Verschachtelungen sichtbar.

else if in ungünstiger Reihenfolge

Prüfe genaue oder hohe Grenzwerte zuerst. Eine früh erfüllte Bedingung verhindert, dass spätere Bedingungen noch geprüft werden.

UND und ODER verwechselt

&& verlangt zwei wahre Teilaussagen. Bei || reicht eine wahre Teilaussage.

keyPressed() und keyPressed verwechselt

Mit Klammern ist es eine Ereignisfunktion. Ohne Klammern ist es ein Wahrheitswert, der während des Gedrückthaltens abgefragt werden kann.

Falsche Anführungszeichen bei key

key enthält ein einzelnes Zeichen. Deshalb vergleichst du mit 'a' und nicht mit "a".

Eine exakte Position wird nie erreicht

Bei größeren Bewegungsschritten kann ein Wert über eine Grenze springen. Verwende am Rand meist >, >=, < oder <= statt ==.
