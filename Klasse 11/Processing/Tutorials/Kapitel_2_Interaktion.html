Was lernst du in diesem Kapitel?

Bisher hat Processing ein Bild gezeichnet und war danach fertig. Jetzt lernst du Programme kennen, die weiterlaufen und auf Eingaben reagieren.

1statischen und aktiven Modus unterscheiden
2setup() und draw() richtig einsetzen
3die Mausposition zum Zeichnen verwenden
4auf Tastendruck und Mausklick reagieren
Vorwissen: Du solltest einfache Formen zeichnen sowie Füll- und Hintergrundfarben festlegen können.
2.1

Programmablauf: statisch und aktiv

2.1.1 Statischer Modus

Im statischen Modus arbeitet Processing die Befehle einmal von oben nach unten ab. Nach der letzten Zeile ist das Programm beendet. So waren die Programme aus Kapitel 1 aufgebaut.

Beispiel: ein fertiges Bild
size(400, 300);
background(230);
fill(40, 130, 210);
ellipse(200, 150, 100, 100);

Jede Zeile wird genau einmal ausgeführt. Der Kreis kann sich danach nicht bewegen und das Programm kann noch nicht auf Eingaben reagieren.

2.1.2 Aktiver Modus mit setup() und draw()

Für Bewegung und Interaktion braucht Processing den aktiven Modus. Dabei übernehmen zwei besondere Bereiche unterschiedliche Aufgaben:

StartProgramm beginnt
→
setup()einmal ausführen
→
draw()immer wieder ausführen
Grundgerüst des aktiven Modus
void setup() {
  size(400, 300);  // Wird einmal ausgeführt
}

void draw() {
  background(230);  // Wird ständig wiederholt
  ellipse(mouseX, mouseY, 40, 40);
}
setup()
Hier stehen Einstellungen, die nur am Anfang benötigt werden, zum Beispiel die Fenstergröße.
draw()
Dieser Code wird wieder und wieder ausgeführt, bis das Programm gestoppt wird.
Merke: Erst läuft setup() einmal. Danach läuft draw() in einer ständigen Wiederholung.

2.1.3 Code-Blöcke und geschweifte Klammern

Die geschweiften Klammern { und } schließen einen Code-Block ein. Sie zeigen Processing, welche Befehle zusammengehören.

Ein Code-Block
void setup() {          // Block beginnt
  size(400, 300);      // Gehört zu setup()
  strokeWeight(3);     // Gehört ebenfalls dazu
}                       // Block endet

Die Befehle innerhalb eines Blocks werden eingerückt. Das verändert die Ausführung nicht, macht den Code aber deutlich leichter lesbar. Processing kann über Bearbeiten → Autoformatierung automatisch einrücken.

Nicht mischen: Sobald du setup() oder draw() verwendest, gehören alle ausführbaren Zeichenbefehle in einen passenden Code-Block.

2.1.4 Frame Rate

Ein einzelner Durchlauf von draw() heißt Frame. Processing versucht normalerweise, etwa 60 Frames pro Sekunde darzustellen. Diese Häufigkeit heißt Frame Rate.

Langsame Wiederholung sichtbar machen
void setup() {
  size(400, 300);
  frameRate(2);  // Höchstens zwei Frames pro Sekunde
}

void draw() {
  println("draw wird ausgeführt");
}

Der Befehl frameRate(2) legt eine Obergrenze von zwei Durchläufen pro Sekunde fest. Für die meisten Programme musst du die voreingestellte Frame Rate nicht verändern.

2.2

Interaktion mit der Maus

2.2.1 Die aktuelle Mausposition

Processing stellt die aktuelle Position des Mauszeigers automatisch bereit:

BegriffBedeutung
mouseXaktuelle x-Koordinate der Maus
mouseYaktuelle y-Koordinate der Maus

Du kannst beide Wörter überall dort einsetzen, wo Processing eine Zahl erwartet. Ihr Wert ändert sich passend zur Mausposition.

Ein Kreis folgt der Maus
void setup() {
  size(500, 350);
}

void draw() {
  background(235);              // Altes Bild übermalen
  fill(30, 150, 210);
  ellipse(mouseX, mouseY, 50, 50); // Maus bestimmt die Position
}
Noch kein Variablenkapitel: mouseX und mouseY sind Variablen, die Processing für dich verwaltet. Im Moment genügt es, ihre Bedeutung zu kennen.

2.2.2 Bewegung oder Spur?

Ob eine Form scheinbar bewegt wird oder eine Spur hinterlässt, hängt davon ab, ob der Hintergrund in jedem Frame neu gezeichnet wird.

background() in draw()
Das vorige Bild wird ständig übermalt. Man sieht nur die aktuelle Position.
Kein background() in draw()
Die alten Zeichnungen bleiben sichtbar. Es entsteht eine Spur.
Mit der Maus Punkte zeichnen
void setup() {
  size(500, 350);
  background(255);  // Nur einmal löschen
  strokeWeight(5);
}

void draw() {
  point(mouseX, mouseY); // Jeder Punkt bleibt erhalten
}
Merke: Die Position von background() entscheidet mit darüber, ob frühere Zeichnungen verschwinden oder sichtbar bleiben.

2.2.3 Die vorherige Mausposition

Zwischen einzelnen Punkten können bei schnellen Mausbewegungen Lücken entstehen. Für eine geschlossene Linie verbindet man die vorige mit der aktuellen Mausposition.

BegriffBedeutung
pmouseXx-Koordinate der Maus im vorherigen Frame
pmouseYy-Koordinate der Maus im vorherigen Frame
Eine durchgehende Linie zeichnen
void setup() {
  size(500, 350);
  background(255);
  strokeWeight(3);
}

void draw() {
  line(pmouseX, pmouseY, mouseX, mouseY);
  // Linie von der vorherigen zur aktuellen Position
}
2.3

Interaktion mit Tasten und Mausklicks

2.3.1 Auf einen Tastendruck reagieren

Der Code-Block von keyPressed() wird genau dann ausgeführt, wenn eine beliebige Taste der Tastatur gedrückt wird.

Tastendruck färbt den Hintergrund schwarz
void setup() {
  size(500, 350);
  background(220);
}

void draw() {
  // Bleibt leer, hält das Programm aber aktiv
}

void keyPressed() {
  background(0); // Wird bei einem Tastendruck ausgeführt
}

Welche Taste gedrückt wurde, unterscheiden wir an dieser Stelle noch nicht. Dafür wären zusätzliche Abfragen nötig.

2.3.2 Auf einen Mausklick reagieren

Für einen Mausklick gibt es den passenden Code-Block mousePressed(). Er wird bei jedem Drücken einer Maustaste einmal ausgeführt.

Mausklick zeichnet einen Kreis
void setup() {
  size(500, 350);
  background(245);
  fill(240, 90, 70);
}

void draw() {
  // Kein background(): gezeichnete Kreise bleiben sichtbar
}

void mousePressed() {
  ellipse(mouseX, mouseY, 40, 40);
  // Ein Kreis an der angeklickten Position
}

2.3.3 Zwei Arten der Interaktion

Die bisherigen Beispiele zeigen zwei verschiedene Arten, wie ein Programm auf die Nutzerin oder den Nutzer reagieren kann:

ArtWann reagiert das Programm?Beispiele
kontinuierlichfortlaufend in jedem FramemouseX, mouseY
punktuellgenau beim Eintreten eines EreignisseskeyPressed(), mousePressed()

Ein solches punktuelles Ereignis nennt man auch Event. Processing ruft den passenden Code-Block automatisch auf, sobald das Event eintritt.

2.4

Typische Fehler

Befehle stehen außerhalb der Code-Blöcke

Im aktiven Modus dürfen Zeichenbefehle nicht lose zwischen setup(), draw() und den Ereignisfunktionen stehen. Verschiebe sie in den passenden Block.

Eine geschweifte Klammer fehlt

Jede öffnende Klammer { benötigt eine schließende Klammer }. Nutze die Autoformatierung, um die Blockstruktur besser zu erkennen.

Die Zeichnung hinterlässt ungewollt eine Spur

Setze background() an den Anfang von draw(), wenn das vorige Bild in jedem Frame gelöscht werden soll.

Die Zeichnung verschwindet sofort wieder

Ein background() in draw() übermalt auch Formen, die bei einem Klick gezeichnet wurden. Entferne es dort, wenn die Formen sichtbar bleiben sollen.

Groß- und Kleinschreibung stimmen nicht

mouseX, mouseY, pmouseX, keyPressed() und mousePressed() müssen exakt geschrieben werden.

Ein Tastendruck oder Mausklick bewirkt nichts

Füge eine draw()-Funktion hinzu, damit das Programm aktiv bleibt. Sie darf leer sein.
